# Redesign (fonts, window hero, rope descent) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bring the approved prototype into the Astro site: Fredoka + Varela Round, new spacing and cards, the interactive window hero, and the character's rope descent to the send button. Everything that works today must keep working.

**Architecture:** The existing components get restyled in place. Two plain TypeScript modules carry the behavior: `hero-window.ts` (boot, buttons, minimize morph, drag, shared position) and `rope-descent.ts` (scroll-planned path, rope, landing). `SceneOpen`'s script wires them together. The rope and climber markup live in a small `RopeClimber.astro` placed once in `index.astro`. The character images are static files in `public/character/`.

**Tech Stack:** Astro 7 (static, `base: /ilay_sandrusi_website/`), CSS, vanilla TS in Astro `<script>` blocks. Google Fonts. No new npm dependencies.

**Spec:** `docs/superpowers/specs/2026-11-27-redesign-design.md`. The visual and behavior reference is `docs/superpowers/specs/2026-11-27-redesign-prototype.html`. When this plan and the prototype disagree on how something looks or moves, the prototype wins.

## Global Constraints

- Fonts: headings `Fredoka` 700 (UI bold bits 500–600). Body text `Varela Round`, which has one weight only, so bold text uses Fredoka 600.
- Colors and tokens stay as they are: `--paper #f6f1e7`, `--ink #171410`, `--accent #ff4b26`, line `2px solid #171410`, hard shadows. Add `--accent-text: #f0421f` for orange text.
- Copy that must stay exactly as written:
  - "יצאתי לרגע" / "גללו למטה"
  - "עובד על זה עכשיו"
  - "יש פה מספיק מקום לפרויקט שלך"
  - "בלי החלון אני לא יכול ללוות אתכם למטה. תשאירו אותו פתוח?"
  - "פתחו לי את החלון"
  - "לחצו לפתיחה"
  - "בבנייה"
- Window opens 1200 ms after load. Minimize and restore morph in 620 ms with `cubic-bezier(.22,1,.36,1)`. The window has no shadow.
- Drag works on desktop only (≥960px), by the bar, inside the left half of `.hero` with a 12px inset. Below 960px there is no drag, and the rope ties at the middle of the window's bottom edge.
- The rope tie point slides along the window's bottom edge with 16px inset. Window at the right end of its area: left corner. At the left end: right corner. Linear between.
- The climber descends only while the window is open (not `is-min`, `is-closed` or `is-boot`). It lands left of `#send`, vertically centered on it, with a 14px gap. If there is no room, it stands on the button's left end (`left = button.left − 0.45·climberWidth`).
- `prefers-reduced-motion`: the window is open immediately, nothing animates, and there is no descent. The climber appears already landed once `#send` is in view.
- Never push or merge to `main`. A push deploys the live site. Work on `redesign/fredoka-window-rope`.

## Review Focus

1. **Fast repeated clicks on − / ⤢ / × while a morph runs.** Expect no stuck state. Clicks during a morph are ignored and the next click works. Pinned in Task 3.
2. **Resizing the browser while the window is dragged, maximized or minimized.** Expect the window to stay inside its area, and the docked bar to stay in its corner. Pinned in Task 4.
3. **Loading the page already scrolled** (refresh mid-page, or the `#contact` link). Expect the climber at its planned spot at once, with no slide from the hero. Pinned in Task 5.
4. **Jumping by header links** (smooth scroll to `#contact`). Expect the climber to follow and land. A scroll that passes the landing point must not leave him floating. Pinned in Task 5.
5. **The form status text appearing** (it changes the layout under the button). Expect the landing to follow the button, so it is recomputed every frame. Pinned in Task 5.

## How checks run (no test runner in this repo)

Each task adds a function to `tests/redesign-checks.js`. This is plain browser JS that defines `window.__redesignChecks = { name: async () => string[] }`. Each function returns a list of failures, and an empty list means it passed. To run the checks:

1. Start the dev server: `npm run dev`.
2. Open `http://localhost:4321/ilay_sandrusi_website/` in the browser pane.
3. Paste the file's contents with the javascript tool, then run `await window.__redesignChecks.<name>()`.

Before each check, finish running animations with `document.getAnimations().forEach(a => a.finish())`. When a check needs a precise layout, set the viewport with `resize_window`.
